# План доработки Sklep (путь A: JavaFX на профессиональном уровне)

Отмечайте выполненное: `- [ ]` → `- [x]`.

**Правила:** код пишет Claude, пользователь проверяет; без git commit/push (коммиты делает пользователь); без комментариев в коде.
После каждого этапа — проверка пользователем и коммит (делает пользователь).
Порядок важен: каждый этап опирается на предыдущий, и после каждого этапа приложение запускается.

## Этап 1. База данных (≈1–2 вечера)

Цель: проверяющий поднимает базу одной командой.

- [ ] `docker-compose.yml` с PostgreSQL (порт, логин, пароль, volume).
- [ ] `db/schema.sql` — таблицы и связи:
  - `accounts` (id, username UNIQUE, password_hash, role, is_active)
  - `profiles` (id, name, surname, address, email, account_id FK)
  - `categories` (id, name UNIQUE)
  - `items` (id, code, name, price, stock, description, image_path, category_id FK)
  - `orders` (id, profile_id FK, created_at, payment_type, status, comment)
  - `order_items` (id, order_id FK, item_id FK, quantity, price) — позиции заказа
  - `cart_items` (id, profile_id FK, item_id FK, quantity) — корзина
- [ ] `db/data.sql` — тестовые данные: админ, 2 клиента, 6 категорий, ~15 товаров.
- [ ] `src/main/resources/db.properties` (url, user, password) + `db.properties.example` в git.
- [ ] `DBManager`: читать настройки, создавать настоящий `Connection`, отдавать репозитории геттерами.

**Готово, когда:** `docker compose up -d` → таблицы с данными созданы, приложение подключается без ошибок.

## Этап 2. Модели и репозитории (≈2–3 вечера)

Цель: надёжный слой доступа к данным.

- [ ] Модели под новую схему: `Item.precision` → `price` (`BigDecimal`), `Item.category`, `Profile.email`.
- [ ] Enum'ы вместо строк: `OrderStatus` (NEW, PAID, SHIPPED, CANCELLED), `PaymentType` (CARD, BLIK, CASH).
- [ ] Модель `OrderItem`; `CartItem` — только корзина.
- [ ] Исправить SQL во всех `update` (пробелы, `SET col = ?`, id в `WHERE`).
- [ ] `getGeneratedKeys()` вместо `getMaxId()`.
- [ ] `try-with-resources` для `PreparedStatement`/`ResultSet`.
- [ ] `getLong` для id; исправить `ProfileRepository.convert/create`, бесконечный цикл в `OrderRepository`.
- [ ] Вместо пустого объекта «не найдено» → `Optional<T>`.
- [ ] Новые методы: `AccountRepository.findByUsername`, `ItemRepository.findByCategory`, `ItemRepository.searchByName`, `OrderRepository.findByProfile`, `CartItemRepository.findByProfile`.
- [ ] Общий код вынести в базовый класс/интерфейс `Repository<T>` (по желанию — хороший плюс).

**Готово, когда:** временный `main` создаёт/читает/меняет/удаляет запись в каждой таблице.

## Этап 3. Слой сервисов (≈2–3 вечера)

Цель: бизнес-логика отдельно от интерфейса — главное, что показывает архитектуру.

- [ ] Зависимость `jbcrypt` — хеширование паролей.
- [ ] `Session` — текущий вошедший пользователь (аккаунт + профиль).
- [ ] `AuthService`: `login` (проверка хеша, блокировки), `register`, `logout`.
- [ ] `CategoryService`, `ItemService` (поиск, фильтр, CRUD для админа, проверка данных).
- [ ] `CartService`: добавить/изменить количество/удалить, посчитать сумму, не больше остатка на складе.
- [ ] `OrderService.placeOrder`: **в одной транзакции** создать заказ, перенести позиции, уменьшить склад, очистить корзину.
- [ ] `UserService` (админ): список, блокировка/разблокировка, удаление.
- [ ] Свои исключения: `ValidationException`, `NotFoundException`, `AuthException`.

**Готово, когда:** вся логика вызывается из кода без интерфейса.

## Этап 5. Экраны по сценариям пользователя (≈5–7 вечеров)

Цель: рабочее приложение от входа до заказа. Данные — только из БД, ничего захардкоженного.

**Гость / вход**
- [ ] Вход: проверка пустых полей, неверный пароль, заблокированный аккаунт, переход по роли.
- [ ] Регистрация (новый экран): логин, пароль ×2, имя, фамилия, адрес, email.
- [ ] Главная для гостя: каталог, «Zaloguj» для покупки.

**Клиент**
- [ ] Каталог: карточки товаров генерируются кодом (`FlowPane`), фильтр по категории, поиск.
- [ ] Карточка товара: фото, цена, описание, остаток, количество, «Dodaj do koszyka».
- [ ] Корзина: `TableView` или список, изменение количества, удаление, сумма, «Płać».
- [ ] Оформление: способ оплаты, комментарий, подтверждение.
- [ ] Мои заказы: список со статусом и составом.

**Администратор**
- [ ] Товары: `TableView`, поиск, добавить/изменить (одна форма для обоих)/удалить с подтверждением.
- [ ] Категории: то же; нельзя удалить категорию с товарами (понятное сообщение).
- [ ] Пользователи: список, блокировка, удаление, просмотр заказов.
- [ ] Заказы: смена статуса.
- [ ] Валидация форм: пустые поля, цена > 0, количество ≥ 0, уникальный код товара.

**Готово, когда:** полный сценарий «регистрация → покупка → админ меняет статус» проходит без ошибок.
